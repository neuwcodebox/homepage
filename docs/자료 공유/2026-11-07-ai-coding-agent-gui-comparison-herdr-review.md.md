# AI 코딩 에이전트 GUI를 찾아서: Orca부터 Herdr까지

최근 AI를 활용해 개발하면서 코드를 직접 작성하거나 읽는 일이 크게 줄었다. 대부분의 작업을 Codex나 Claude Code에 맡기고, 결과를 Git diff로 검토한 뒤 필요한 수정사항을 다시 지시하는 방식이다.

이런 작업 방식에서는 코드 에디터보다 여러 AI 에이전트와 프로젝트를 관리하는 GUI가 더 중요하다.

그동안 Orca, Paseo, T3 Code 등을 사용했지만 각각 아쉬운 점이 있었다. 대안을 찾던 중 Zed와 Delta도 조사했고, 최근에는 Herdr를 직접 설치해 사용해 봤다.

## 1. 원하는 개발 환경

현재 Windows와 WSL2를 함께 사용하며 Codex와 Claude Code를 기존 구독 계정으로 실행한다.

주로 다음과 같은 방식으로 작업한다.

1. 프로젝트를 선택하고 AI 에이전트에 작업을 지시한다.
    
2. 여러 프로젝트와 세션을 오가며 작업을 진행한다.
    
3. 완료된 작업의 Git diff를 검토한다.
    
4. 필요한 수정사항을 다시 지시한다.
    

따라서 다음 요소를 중요하게 생각한다.

- 프로젝트 관리: 여러 프로젝트와 AI 세션을 편리하게 관리
    
- 구조화된 대화 UI: Markdown, 코드 블록, 도구 호출, 승인 요청 등을 보기 좋게 표시
    
- Git diff 리뷰: AI가 수정한 코드를 편리하게 검토
    
- Windows·WSL 연동: Windows GUI에서 WSL 내부의 프로젝트와 CLI 사용
    
- 경량성: 여러 세션을 실행해도 쾌적한 UI
    
- 기본 UI 완성도: 별도의 커스터마이징 없이도 주요 기능 사용 가능
    

특히 기본 UI의 완성도를 중요하게 생각한다. 커스터마이징 자체가 싫은 것은 아니지만, 기본적인 기능을 사용하기 위해 외부 플러그인을 찾아 설치하거나 직접 화면을 구성하고 싶지는 않다.

## 2. 기존에 사용한 도구들

### Orca

Orca는 지금까지 사용한 도구 중 기능적으로 가장 만족스러웠다.

프로젝트와 AI 세션을 관리하기 편하고, 구조화된 채팅과 Git 변경사항 검토 등 필요한 기능도 대부분 갖추고 있다.

다만 몇 가지 문제가 있다.

- 전체적으로 무겁고 UI 반응이 느릴 때가 있다.
    
- WSL 프로젝트에서 Git diff를 불러오는 속도가 느리다.
    
- 에이전트 훅 처리로 인한 지연을 경험했다.
    
- 일부 버전에서 불필요한 Codex 알림이 나타나는 문제가 있었다.
    
- WSL 환경에서는 네이티브 구조화 채팅 지원에 제약이 있다.
    

기능은 만족스럽지만 성능과 안정성이 아쉽다.

### Paseo

Paseo는 비교적 가볍고 AI 에이전트 관리에 집중한 도구다.

그러나 Windows와 WSL을 함께 사용하는 환경에서는 데몬을 별도로 구성하고 관리해야 하는 점이 번거로웠다.

사용 경험 자체는 나쁘지 않지만, 환경 설정과 관리에 신경 써야 한다는 점이 아쉬웠다.

### T3 Code

T3 Code는 깔끔하고 가벼운 UI가 인상적이었다.

특히 Windows와 WSL의 연동이 편리했고, AI와 대화하는 경험도 자연스러웠다.

하지만 프로젝트 관리와 파일 탐색 등 기본적인 작업공간 기능이 부족했다. Git diff 리뷰도 Orca에 비하면 아쉬웠다.

2026년 11월 초까지 Git diff 성능, 세션 복구, 승인 처리 등 여러 개선이 이루어졌지만, 사용하면서 느꼈던 핵심적인 불편함이 해결됐다고 보기는 어려웠다.

따라서 현재로서는 다시 사용해 볼 이유가 크지 않다고 판단했다.

## 3. 새롭게 조사한 Zed와 Delta

### Zed

Zed는 Rust 기반의 네이티브 코드 에디터다.

최근에는 Agentic Layout, Parallel Agents, Threads Sidebar 등 AI 에이전트 관련 기능이 상당히 강화됐다.

Codex와 Claude Code를 실행하고, 여러 세션을 관리하며, Git 변경사항을 검토할 수 있다.

단순히 에디터 옆에 채팅창을 붙인 수준은 아니다.

그러나 Zed는 여전히 코드 에디터를 중심으로 설계된 제품이다.

코드를 직접 작성하거나 탐색하는 일이 많다면 좋은 선택이겠지만, 내 경우에는 이러한 기능을 거의 사용하지 않는다.

Windows·WSL 환경의 외부 에이전트 연동에도 일부 제약이 있어 우선순위를 낮췄다.

### Delta

Delta는 Zed 개발사에서 만든 별도의 AI 협업 도구다.

AI 대화와 코드 변경 이력을 연결하고, 작업 과정과 코드 리뷰를 통합하는 접근 방식이 흥미로웠다.

하지만 조사 당시에는 WSL2 지원과 기존 Codex CLI 연동이 충분하지 않았다.

또한 클라우드 동기화를 활용하는 구조라 회사 개발 환경에서 사용하기에는 별도의 보안 검토가 필요하다.

아직은 도입하기 이르다고 판단했다.

## 4. Herdr 직접 사용해 보기

Herdr는 Rust 기반의 터미널 및 AI 에이전트 관리 도구다.

기존 TUI 외에 별도의 데스크톱 앱을 제공한다.

공식 사이트: [Herdr](https://herdr.dev/?utm_source=chatgpt.com)

Herdr App은 GUI와 에이전트 실행 환경이 분리되어 있다.

|구성 요소|역할|
|---|---|
|Herdr App|데스크톱 GUI|
|Herdr Core|터미널 및 에이전트 실행·세션 관리|
|Herdr TUI|터미널 기반 인터페이스|

이 구조 덕분에 GUI를 종료하더라도 Core가 실행 중이면 에이전트 작업을 유지할 수 있다.

### Windows + WSL2 연결

Windows에 Herdr App을 설치하고 WSL2에는 Herdr Core를 설치했다.

Herdr App은 SSH를 통한 원격 머신 연결을 지원하므로, WSL에 SSH 서버를 구성하고 Windows에서 연결하는 방식으로 사용했다.

```
Windows
└── Herdr App
    └── SSH
        └── WSL2
            ├── Herdr Core
            ├── Codex CLI
            └── Claude Code
```

WSL 전용 자동 연동 기능은 아니지만 정상적으로 연결해 사용할 수 있었다.

다만 T3 Code처럼 별도 설정 없이 WSL 환경을 자연스럽게 사용하는 방식과 비교하면 초기 구성이 번거롭다.

### 첫인상: 확실히 가볍다

Herdr를 실행하면서 가장 먼저 체감한 장점은 경량성이었다.

Orca와 비교하면 UI가 확실히 가볍고 반응도 빨랐다.

여러 터미널과 에이전트를 실행하는 용도로 설계된 만큼 기본 동작도 단순하다.

하지만 실제로 사용해 보니 이러한 단순함에는 아쉬운 점도 있었다.

### 프로젝트보다 터미널이 중심이다

Herdr는 머신, Space, Tab, Pane으로 작업 환경을 구성한다.

왼쪽 사이드바에는 머신과 Space 목록이 세로로 표시되고, 선택한 Space의 탭은 상단 바에 가로로 열린다.

Space는 일반적인 IDE의 프로젝트 개념과는 다르다.

새 Space를 만들면 터미널이 실행되고, 해당 터미널의 작업 디렉터리를 기준으로 작업공간이 구성된다.

같은 Space에서 탭을 추가하면 여러 터미널이나 AI 에이전트를 실행할 수 있다.

예를 들어 하나의 Space에서 Codex와 Claude Code를 각각 다른 탭으로 열어 작업하는 방식이다.

그러나 프로젝트를 미리 등록해 두고 필요할 때 AI 세션을 생성하는 방식은 아니다. Space가 터미널 실행과 밀접하게 연결되어 있다.

개인적으로는 이 방식이 불편했다.

여러 프로젝트를 등록해 두고 필요한 작업을 선택하는 방식에 익숙하다 보니, 터미널을 중심으로 작업공간을 관리해야 한다는 점이 마음에 들지 않았다.

### Files와 Changes 패널의 완성도

Herdr는 기본 UI에 Files와 Changes 패널을 제공한다.

- Files: 프로젝트 파일 탐색 및 미리보기
    
- Changes: Git 변경사항 목록 및 diff 확인
    

기본 기능이 있다는 점은 좋지만, 실제 사용 경험은 아쉬웠다.

Files 패널에서는 파일 종류에 따라 문법 강조가 제대로 적용되지 않는 경우가 많았다.

Changes 패널은 추가·삭제된 줄을 색상으로 구분하지만, 코드 문법 강조 등 가독성을 높이는 기능이 부족했다.

코드를 직접 작성하는 일이 거의 없더라도 AI가 수정한 내용은 확인해야 한다. 따라서 Git diff의 가독성은 내게 중요한 요소다.

Herdr의 Files·Changes 패널은 기본적인 확인 용도로는 사용할 수 있지만, 코드 리뷰 경험이 만족스럽지는 않았다.

### 에이전트 관리와 협업

Herdr는 여러 에이전트를 실행하고 상태를 추적할 수 있다.

또한 Herdr Core의 `hc` 명령을 이용하면 에이전트가 다른 에이전트를 실행하거나 작업을 위임할 수도 있다.

에이전트에게 `hc --skill`을 확인하도록 하고 자연어로 다른 에이전트에게 작업을 맡기라고 지시하는 방식도 가능하다.

그러나 GUI에서 이러한 작업을 직관적으로 제어하는 기능은 제한적이다.

에이전트 간 협업을 위해 CLI 명령이나 에이전트의 도구 사용에 의존하는 방식은 내 취향에 맞지 않았다.

GUI 앱을 사용하는 만큼 주요 작업을 GUI에서 편리하게 처리할 수 있기를 기대했기 때문이다.

## 5. Herdr의 커스터마이징 기능

Herdr의 또 다른 특징은 강력한 UI 커스터마이징 기능이다.

레이아웃과 패널을 JavaScript 기반 모드로 수정할 수 있으며, AI에게 직접 화면을 만들어 달라고 요청하는 것도 가능하다.

공식 갤러리에는 커뮤니티가 제작한 다양한 확장 기능이 공개되어 있다.

|확장|주요 기능|
|---|---|
|Shepherdr|작업 큐, 에이전트 배정, 워크트리 관리|
|Herdr T3|세션 정리, Inbox, Snooze|
|Space Folders|Space 폴더 그룹화|
|Main + Usage|사용량 표시, 세션 검색·재개|
|Redline|PR·MR 코드 리뷰 기능|

이러한 확장을 사용하면 기본 UI에서 부족했던 기능 일부를 보완할 수 있다.

하지만 이것이 오히려 Herdr에 대한 평가를 낮춘 이유이기도 하다.

커스터마이징으로 다양한 기능을 구현할 수 있다는 것은 장점이다. 그러나 기본적인 작업공간 관리나 코드 리뷰 경험을 개선하기 위해 별도 모드를 찾아 설치해야 한다는 것은 아쉽다.

커뮤니티 모드를 여러 개 조합하면 기능은 풍부해질 수 있겠지만, 업데이트와 호환성 등 관리할 요소도 늘어난다.

개인적으로는 이런 방식보다 기본 UI 자체가 충분히 완성된 제품을 선호한다.

결국 Herdr는 잠깐 사용한 뒤 제거했다.

## 6. 전체 비교

2026년 11월 7일 기준으로 조사하거나 사용한 제품들을 정리하면 다음과 같다.

|제품|장점|아쉬운 점|
|---|---|---|
|Orca|풍부한 AI 세션·프로젝트 관리, 구조화된 대화 UI|무거운 UI, 성능·안정성 문제|
|Paseo|비교적 가벼운 AI 에이전트 관리|Windows·WSL 설정 및 데몬 관리|
|T3 Code|가볍고 깔끔한 UI, 편리한 WSL 연동|프로젝트·파일 탐색 등 기본 기능 부족|
|Herdr|매우 가벼운 UI, 세션 유지, 높은 확장성|터미널 중심 UX, 기본 UI 완성도 부족|
|Zed|네이티브 성능, 코드 편집·diff 기능|에디터 중심 설계, 일부 WSL 연동 문제|
|Delta|AI 대화와 코드 변경 이력 통합|WSL·CLI 연동 제약, 클라우드 의존성|

각 제품은 비슷한 기능을 제공하더라도 설계 방향이 다르다.

Orca, Paseo, T3 Code는 AI 에이전트를 사용하는 작업공간에 집중한다.

Herdr는 터미널과 에이전트 프로세스를 관리하는 데 집중하고, Zed는 코드 편집과 AI 기능의 통합에 강점이 있다.

Delta는 AI 작업 기록과 코드 변경사항을 함께 관리하는 새로운 협업 환경을 지향한다.

## 7. 마무리

Herdr는 직접 사용해 보니 장단점이 명확했다.

가볍고 빠르다는 점은 확실히 만족스러웠다. WSL2 환경에서도 SSH를 통해 연결할 수 있었고, 여러 Codex·Claude 세션을 실행하는 것도 가능했다.

그러나 프로젝트보다 터미널을 중심으로 구성된 작업공간, 부족한 Files·Changes 기능, CLI에 의존하는 에이전트 협업 방식은 기대와 달랐다.

커스터마이징으로 기능을 확장할 수 있지만, 기본적인 사용 경험을 보완하기 위해 커뮤니티 모드에 의존하고 싶지는 않았다.

다른 도구들도 마찬가지로 각자의 장단점이 있었다.

현재는 Orca를 주로 사용하고 있지만, 여전히 성능과 안정성에 아쉬움이 있다. T3 Code의 가벼운 UI도 마음에 들었지만 기능이 부족했고, Paseo 역시 설정과 관리 측면에서 불편했다.

아직 개인적인 사용 방식에 완전히 만족스러운 도구를 찾지는 못했다.

당분간은 Orca를 사용하면서 다른 도구들의 발전을 지켜볼 생각이다.

이 글은 사람의 확인을 거쳤으나 AI로 작성되어 부정확할 수 있습니다.
